# Card pass report outline

Lead with the cards and resulting supported behavior. Use evidence from the actual pass.

- Scope: issue, branch/base, requested set/printing, unique cards reviewed, wired/blocked/out-of-scope counts, inventory before/after.
- Coverage table: card ID/name, exact printing/source, implementation or blocker, relevant tests. Group repetitive mechanics when useful.
- Readings: confirmed ruling and source reply/R-ID; proposed interpretation and alternatives; unanswered question and affected cards. Never promote a proposal to a ruling by silence.
- Shared behavior: new mechanics, costs/timing/negation, state and choices, compatibility with old saves/replays.
- Client-lane items: command/choice/view change, authorized viewer(s), required controls/assets, existing UI support, remaining review.
- Artwork: exact scans and unresolved requests, generated pack tag/hash/image count, installation/coverage status, publication status.
- Validation: exact commands, suite counts and failures, deterministic comparison if run, CI/native/human checks actually completed, explicit gaps.
- Handoff: reviewable PR/commit, known remainders and next actions. Keep any required attribution/footer from the task.
