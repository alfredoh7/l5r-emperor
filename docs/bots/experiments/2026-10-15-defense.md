# 2026-10-15 defense (pre-registration, round 2)

- Issue / branch / arm: #963, `claude/963-bot-defense` (stacked on round 1's branch; the round 1 code is present but off), arm `defense` (`BotContext.UseInformedDefense`, default off).
- Champion: `main` (flag off).
- **Hypothesis.** When defending, the champion sends *every* unbowed home Personality to the battlefield with the largest visible attacking army, whether or not that Province would fall anyway, and
  whether or not that army can be beaten (BOT_LOGIC section 6). Rules as the engine applies them: the larger Force wins and the loser's whole army is destroyed; a Province falls only if attackers' Force
  exceeds defenders' Force plus the Province's Strength. A defense is therefore worth sending only where it **wins** (attackers destroyed, nothing lost) or where it is the **difference between a Province
  standing and falling**. Elsewhere it risks the defenders for nothing, and sending everything to the biggest army can ignore a smaller army the defenders would beat.
- **Change (general; no card or deck named).** For the defense assignment: (1) if some contested battlefield can be won by the offered defenders, go to the one that destroys the biggest army, preferring one
  where the Province would otherwise fall; (2) else if some Province would fall but stands once the defenders are added, defend the one with the highest Strength; (3) else (the Province stands anyway or the
  defense cannot change the outcome) keep the units home. The last-stand rule (every remaining Province falls) and the Cavalry rules are untouched. Reads only the seat's own PlayerView.
- **Expected effect:** +1 to +3 points against the champion, overall (every deck defends); more in games with attacks on several Provinces.
- **Design:** primary test is `same` pairing for the reason given in the round 1 pre-registration (only altered games can be discordant; `same` pairing is deterministic).
- **Decisive test.** Mode `dev`, pairing `same`, seeds 24-35 (`L5R_TOURN_SEED_START=24 L5R_TOURN_SEEDS=12`; fresh block) = 864 pairs, 1,728 games, about 32 minutes. Primary metric: pairs won both vs lost both,
  exact one-sided sign test, challenger better, **p < 0.025**. Also: challenger win rate >= 51%; zero bot stalls and no more of any other soundness finding than the champion; no deck (>= 40 decided games piloted)
  below 35% for the challenger where the champion is at 50% or more; provinces-left and Honor margins not negative. Fixed sample, no extension.
- **Confirmation (only if dev passes):** mode `holdout`, pairing `same`, seeds 13-22 (600 games): one-sided p < 0.10, win rate >= 50%, zero bot stalls.
- **Decision rule:** promote-candidate only if dev and confirmation both pass; otherwise recorded as negative or inconclusive and the flag stays off.

## Result (fill in after the single run; the plan above is not edited)

- Command: `L5R_TOURN_CHAL=defense ... L5R_TOURN_SEED_START=24 L5R_TOURN_SEEDS=12` (1,728 games, 36 min).

  Margins: provinces +0.05, Honor +0.1, Personalities +0.03. No deck collapse (Lion preset 30%, Phoenix Talons 24%, Scottish Lion 19%, all below 50% for the champion too).
- By the registered rule (paired test p < 0.025, win rate >= 51%, soundness, margins) the dev test **passes, narrowly**: 51.4% clears the 51% floor by 0.4 points and the plain win-rate test alone would not.
