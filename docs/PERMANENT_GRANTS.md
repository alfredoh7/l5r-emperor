# Permanent keyword and ability presentation

Issue [#213](https://github.com/alfredoh7/l5r-emperor/issues/213), implementation [#256](https://github.com/alfredoh7/l5r-emperor/pull/256). Built on the approved UI consolidation in [#248](https://github.com/alfredoh7/l5r-emperor/pull/248); the separate Duel Demo #220 is excluded.

## Player behavior

In-play cards with public permanent grants get A's small gold knot in their token rail. One change shows only the knot; multiple changes add a live white count. Printed keywords and token quantities do not count as grants. Permanent keywords no longer cover the card face with a text band.

Hovering the seal opens B's worn lacquer panel, with distinct artwork for keywords, stat changes and ability text. Each entry states its duration. Temporary and attachment-dependent changes are separated from permanent ones. A common source appears once in the footer; multiple sources are identified under their entries. Unavailable source identity is shown as unavailable, never an internal ID or an inferred hidden card.

Clicking the seal selects its own card, including independently bowed attachments. The right inspector puts the changes before the full card face and uses its existing scroll area for long text. A source still present in the public snapshot can be inspected using the source link. Both are read-only navigation, not game commands. Keyboard focus exposes the same information; Escape dismisses the focus panel. Native and projected hover paths are separate to avoid duplicate popups.

The rail retains normal density for up to four token types; five/six compress as previously requested. Existing bowed/attachment placement and full card scans are preserved. No new animation is added; reduced-motion behavior stays supported.

## Engine contract and limits

`GrantedKeyword` already supplies the keyword, source and duration. This UI consumes it directly. An optional trailing `CardView.GrantedEffects` field now projects existing action-protection effects as read-only `GrantedEffectView(Name, Text, Source, Duration, Kind)` entries. This exposes existing engine behavior; it does not implement a new card effect or let the client grant anything. Hidden cards omit metadata, old payloads deserialize without the new field, and public view arrays are detached from engine state.

Existing `AppliedModifier` entries are turn-duration effects and are labeled accordingly. The UI never infers a permanent bonus from current minus printed Force. Printed traits, token effects, attached bonuses and granted traits remain distinct.

**Spirit of the Berserker is not wired as a playable card in this baseline.** The concept's Berserker / +2 Force / Reaction combination is reproduced using explicitly staged, read-only view fixtures. A generic permanent-stat or Reaction-granting engine primitive is not supplied by this task. Screenshots demonstrate the approved presentation and public data contract, not acceptance of those illustrative card mechanics. Live snapshots currently provide granted keywords, existing action protections and turn modifiers.

## Review and reproduction

- [Native screenshots and approved source comparison](screenshots/permanent-grants/index.html)
- [Artwork provenance and crop geometry](../assets/ui/permanent-grants/README.md)
- `bash tools/check-permanent-grants.sh` builds/imports and runs native hover/click/focus, overflow, full-game and token-rail regressions on a graphical desktop.
- `bash tools/check.sh --skip-client` checks the shared view contract, turn expiry, serialization, hidden information and existing deterministic suites.
- `res://PermanentGrantProbe.tscn -- --interactive` opens the isolated artwork review; all effect examples there are staged views.
- Full-game capture modes `published-grants` and `published-grants-detail` also stage public views only, and require an explicit `--capture=...` invocation. Normal play never injects these fixtures.

Final run results and remaining acceptance boundaries are in [VALIDATION.md](screenshots/permanent-grants/VALIDATION.md).

The launcher also pins the existing v3 WebP85 artwork release for six newer main-branch printings. The regenerated bytes match the published archive exactly; the mandatory optimized-artwork workflow remains intact.
