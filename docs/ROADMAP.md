# Roadmap

A living checklist of missing rules-engine mechanics and open visual/UI feature requests. Unlike `docs/handoffs/tasks/` (one record per task branch) and `docs/decisions/` (one record per durable decision), this file is edited in place as items ship — it is not regenerated per branch and does not itself carry task evidence. `docs/PROJECT_STATUS.md` remains the source of truth for current shared milestone status; `docs/NEXT_PHASE.md` for the broad phase sequence. This document is the granular feature/mechanic level underneath both.

Update this file as part of the PR that ships (or meaningfully advances) an item: move it to Done with the issue/PR that closed it, or add a new row when a gap is identified. Issue: [#86](https://github.com/alfredoh7/l5r-emperor/issues/86).

**Card inventory:** [docs/CARD_INVENTORY.xlsx](CARD_INVENTORY.xlsx) lists every card in the reference catalogue (`content/deck-pool.json`) with its Type and Wired/Unwired status. It's generated, not hand-edited — regenerate it with `python3 tools/content/build_card_inventory.py` as part of any PR that ships a new content wave (a new `content/published/*.json` file).

Status values: **Not started** / **In progress** / **Done**.

## Rules-engine mechanics

Confirmed by direct source audit of `src/L5R.Core` on 2026-09-09, not by absence of a card that would need them.

### Not yet implemented

| Mechanic | Status | Notes |
|---|---|---|
| Dishonor / Rehonor as general actions | Partial ([#90](https://github.com/alfredoh7/l5r-emperor/pull/91)) | `Rehonor(card)` and the shared `MarkDead`/`MakeDead` primitives now exist (dishonorable-death Honor loss centralized; a discarded card can become honorably dead independently of destruction) — but no action yet *dishonors* a Personality outright beyond the entry-time `enters-dishonored` Effect, and the "rehonor instead of gaining Honor" substitution (core rules p. 98–100) still has no engine hook. |
| Reactions to Ranged/Melee Attacks | Done ([#90](https://github.com/alfredoh7/l5r-emperor/pull/91)) | The Attack primitive now opens a real Reaction window (mutable `PendingAttack.Strength`, either side may raise/lower/negate) before resolving — but only when a reaction is actually possible; no published card provides one yet, only training fixtures. |
| Dueling | Not started | No performer/target selection, duel stat, Focus mechanism, Focus Effects, Duelist keyword, or resolution/winner/consequence application exists anywhere in the engine. This is one of the largest single gaps — several already-triaged Strongholds and many catalogue Personalities need it. |
| Engage reaction-timing window | Not started | See [#15](https://github.com/alfredoh7/l5r-emperor/issues/15) — no window exists for "After engaging" triggers generally (Naval Invasion currently short-circuits this by resolving inline rather than through a real Reaction window). |
| Events Phase: Region/Celestial-specific resolution | Partial | Region attachment and Celestial entry are described in the core rules doc; the Events Phase itself (Straighten→Events ordering) is implemented, but Region/Celestial card types have no published examples yet to validate against. |

### Built as general primitives, narrowly exercised so far

These exist as reusable engine shapes, not just one-off card hacks — but only 1–4 published cards currently exercise each, so edge cases beyond what those cards need are untested.

| Entering-play Reaction window | Done (primitive) | [#82](https://github.com/alfredoh7/l5r-emperor/issues/82)/[#83](https://github.com/alfredoh7/l5r-emperor/pull/83), generalized [#152](https://github.com/alfredoh7/l5r-emperor/issues/152) | `Timing:"Reaction"` + `Trigger:"own-enters-play"`, composes correctly with Proclaim in the same window. Repeatable each time the same card re-enters play, not just once ever — opening the window clears any earlier usage record. `PendingChoice.ActingPlayerId` now controls who regains priority once the window closes, defaulting to `ActivePlayerId` (Purchase/attackReaction, unaffected) but set to the opponent for an Action-phase entry (Equip/Terrain), so the normal any-action-cedes-priority rule still holds. Exercising a Terrain's own ability (for the first time ever) surfaced two latent bugs, both fixed: `ValidateAbility`'s zone check assumed every Strategy source is always in Hand (a Terrain stays in `Zone.Battlefield`), and `UseAbility`'s tail unconditionally discarded any Strategy source afterward (would have discarded a Terrain off the battlefield). Only this one trigger is generalized — other Reaction triggers ("After engaging," "Before an action's effects resolve," "After a duel," etc.) would each need their own window built when a card needs one. No mechanism yet returns a card to play from a discard pile/deck, so that entry path is unexercised by any real card; the hook needs no further change to support it once built. |
| Reconnaissance | Done (primitive) | [#93](https://github.com/alfredoh7/l5r-emperor/issues/93)/[#101](https://github.com/alfredoh7/l5r-emperor/issues/101) | `ProvinceState.Reconnaissance` (a per-player bool, indexed by player id, on every province of both players), `HasReconnaissance`/`GrantReconnaissance`, and an `enemy-province` targeting shape keyed by index (`GameCommand.Province`) rather than a card id. Once granted it persists — no ability clears it — except that it resets to No for both players once the battle at that province resolves (`ResolveBattle`, regardless of outcome); a province refilling with a new card or being destroyed does not clear it on its own. A check gates only the Reconnaissance-dependent portion of an ability's effect; the rest still proceeds regardless (see `training-reconnaissance-strike`). No published card exercises it yet — training fixtures (`training-scout`) only — and no UI surfacing exists (a real card would need a "pick an enemy province" affordance the generic action-discovery query doesn't build yet, since `AbilityActions()` only enumerates card-id targets today). Daidoji Kitahime, Hiruma Akio, Hiruma Nitani, Hiruma Sniper, Hiruma Tensin, Toritaka Chokichi, Yoritomo Haruhiko, Strategic Strike, Spirit of the Scout, and The Otoro Estate (Stronghold) are the known candidates that need it. |
| Tactician keyword / Tactical Advantage | Done (primitive) | [#104](https://github.com/alfredoh7/l5r-emperor/issues/104) | A universal, tireless `PlayerAbility` (`tactical-advantage`, like Lobby/Shunya's Sacrifice): discard a card and choose your performing Tactician at this battlefield (no "unbowed" qualifier) to give it Force equal to the discard's Focus Value. Exempted from the normal once-per-turn dedupe entirely ("any number of times per turn" — its own cost is the only real limit), a first for the engine. Battle-timing by default; a future card granting an Action-segment variant (an Akodo Ayumu variant) would need its own catalog entry reusing the same `UseAbility` case, not a change to this one. No published card exercises it yet, only `training-tactician`. |
| Conqueror keyword | Done (primitive) | [#104](https://github.com/alfredoh7/l5r-emperor/issues/104) | `ResolveBattle` checks the attacker's surviving attacking Personalities for the Conqueror keyword after a win. Zero or one eligible candidate resolves immediately (nothing to choose); two or more open a new `PendingConqueror`/`PendingChoice("conqueror")` pair so the attacker can pick — the first pending-choice split out of battle resolution itself, via a new `FinishBattleResolution` tail shared by both the immediate and deferred paths. | Kensai keyword | Done (primitive) | [#104](https://github.com/alfredoh7/l5r-emperor/issues/104), fixed [#109](https://github.com/alfredoh7/l5r-emperor/issues/109) | `AttachmentAllowed` now branches by Armor vs. Weapon: Armor stays capped at one; Weapon is capped at two when the wielder has Kensai (printed or granted) or the equipping/already-attached Weapon carries the `Kama` keyword — the two allowances do not stack, so a Kensai wielding a Kama is still capped at two, not three. | Cavalry Maneuvers Segment | Done (primitive) | [#107](https://github.com/alfredoh7/l5r-emperor/issues/107) | Two new phases, `CavalryDeclaration`/`CavalryDefense`, follow `AttackDeclaration`/`DefenseAssignment` (Infantry Maneuvers) in the same attacker-then-defender order — `DeclareAttack`/`AssignDefense`/`Assign` are now phase-aware rather than single-step. There is no printed "Infantry" keyword: `IsCavalryUnit` treats a unit (a Personality plus its attached Followers) as Cavalry only if the Personality *and every attached Follower* carry the Cavalry keyword; a unit missing Cavalry anywhere in it must assign, if at all, during Infantry Maneuvers regardless of how many of its other cards are Cavalry. | Honor-loss immunity | Done (primitive) | [#138](https://github.com/alfredoh7/l5r-emperor/issues/138) | A Stronghold's printed passive ("you do not lose Honor from [Clan] and Fate cards you own") can negate a Honor loss outright. `GainHonor` takes an optional source `CardInstance`, threaded through the call sites where a printed ability actually causes the change (Dishonorable death, Law of Darkness Dojo, training strikes) — not the innate battle-Force-math gains/losses, which have no single card as their cause. A data-driven `HonorLossImmunity` table, keyed by the losing player's own Stronghold `Effect`, makes adding another Stronghold's variant trivial; this is the recurring pattern 6+ published Strongholds share. Only losses are covered so far — no card negates a gain yet, but the mechanism doesn't assume that's permanent. A one-off/reactive negation (a Reaction ability negating one specific loss) is a distinct shape, deliberately not built without a concrete card driving it. No published card exercises the primitive yet, only `training-honor-immune-stronghold`/`training-spider-honor-loss`/`training-honor-cost-strategy`. |
| Terrain | Done (primitive) | [#135](https://github.com/alfredoh7/l5r-emperor/issues/135) | A Terrain-keyword Strategy plays via the existing `PlayStrategy` Battle action, branching before the usual Personality-target requirement: no target, enforces at most one Terrain per battlefield (checked against `Zone.Battlefield` presence at the current province, the engine default since no published card overrides it yet), and lands in `Zone.Battlefield` instead of an immediate discard. `FinishBattleResolution` discards any Terrain at the resolving battlefield after all Force/Honor/destruction effects are applied, never carrying it into a later battle or turn. | Loyal keyword | Done (primitive) | [#142](https://github.com/alfredoh7/l5r-emperor/issues/142) | `CardDefinition.Clans` (string array, overrides the single `Clan` field when present) models a Personality aligned with more than one Clan; a new `ClanAlignments(card)` helper returns it (or `[Clan]` when absent). `QuotePurchase` rejects recruiting a Loyal Personality (`Keyword(card,"Loyal")`) whose alignments don't include the recruiting player's Clan — a multi-aligned Loyal Personality recruits normally for any of them. | Generic keyword-satisfaction primitive | Done (primitive) | [#144](https://github.com/alfredoh7/l5r-emperor/issues/144) | A large set of keywords (Berserker, Magistrate, Ninja, Ronin, and dozens more — see the issue) have no mechanical rule of their own but still satisfy a "Target your X Personality" / "Choose your performing X Personality" condition, in addition to (not instead of) any mechanical ability a keyword like Tactician/Shugenja/Cavalry already carries. | Generic "without attachments" filter | Done (primitive) | [#158](https://github.com/alfredoh7/l5r-emperor/issues/158) | "Without attachments" is a boolean, never a count: new `HasAttachments(card)` is true for any attached Follower/Item/Spell, or a token specifically designated as one (`AttachmentTokenTypes = ["Follower","Weapon","Armor"]`) — an ordinary stat/status token (Fire, Poison, Madness) does not count. New `AbilityDefinition.RequireNoAttachments` layers this onto whichever `Target` category is already chosen (e.g. `"enemy-force"` + `RequireNoAttachments: true`) instead of a new category per combination, matching "Target an enemy card without attachments" verbatim (Thunderous Legion, Elite Sentry, and several more from the Follower Wave 2 triage) — automatically respected by the offered-action legal-targets list too, since candidates are generically re-validated through the same check. Deferred: the printed "exception" case where a specific Attack overrides the no-attachments rule (e.g. Elephant Caravan/Strategic Strike's Reconnaissance-gated exception) has no imported card to exercise it yet. |
| Province adjacency | Done (primitive) | [#160](https://github.com/alfredoh7/l5r-emperor/issues/160) | A player's 4 provinces sit in a line (1-2, 2-3, 3-4 adjacent); a destroyed province is skipped and its former neighbors become directly adjacent instead, compounding across multiple destructions (both middle provinces destroyed makes the two ends adjacent) — the "provinces slide together" model. New `AdjacentProvinces(playerId, index)` derives this on demand from each province's existing `Destroyed` flag, scanning outward in both directions — no new state, no adjacency table to keep in sync, no renumbering of any existing fixed-index province reference elsewhere in the engine. New Target category `"personality-at-adjacent-battlefield"`, the one deliberate exception to the blanket "Battle-timing targets must be at the current battlefield" check. Confirmed general beyond the usual 4: the loop bound is `Provinces.Count`, not a literal 4, so a 5th/6th province (added the way the physical game does it — fate/dynasty decks shift a card-space apart and a new face-down dynasty card is placed in the gap, numbered 5/6) is just another appended `ProvinceState`; a test proves adjacency and destruction-reconnection both still work at 6 provinces with no code change. Infrastructure only — no published card needs adjacency yet, built as the first prerequisite for the aggregate/group Force effects primitive below. |

## Content coverage

Published (playable) card count as of 2026-09-11: **181** — pinned Lion/Crane 40, Vanilla Wave 1 (61 ability-free), Stronghold Waves 1–3 (7 total), Personality Waves 1–7 (19 total), Follower Waves 1–6 (45 total), Strategy Waves 1–2 (7 total), Item Wave 1 (2). The full Emperor-legal reference catalogue (`content/deck-pool.json`) has 2,143 cards; the wider catalogue is reference-only until a card is explicitly wired up (`docs/rules/LION_CRANE_COVERAGE.md`, `AGENTS.md` — never silently turn an unsupported effect into a blank playable card).

Personality wave 7 ([#186](https://github.com/alfredoh7/l5r-emperor/issues/186)) shipped Utaku Chikako, the first real card exercising the Dishonor/Rehonor Personal-Honor override plus a straightforward Limited ability (gain 2 Honor; may not declare an attack this turn). Also revisits and confirms Justice of the Crane's own deferred "printed Magistrate" bonus (#179/#180/#181): its `PrintedKeyword` check already correctly reads only the wielder's own printed Keywords, ignoring any attachment/permanent-effect grant (including Justice of the Crane's own), so no change was needed there beyond routing its Dishonor through the newly-named `Dishonor()` helper.

Personality wave 6 and Follower wave 6 ([#184](https://github.com/alfredoh7/l5r-emperor/issues/184)) shipped the first real cards for the Reserve/Stalwart primitives: Hida Kurabi and Matsu Ryohei (Destined/Reserve and Cavalry/Destined/Reserve, Personality Wave 6), Shiba Jikaro (Stalwart, Personality Wave 6), and Floating Reserve (a pure Reserve Follower, Follower Wave 6) — all four are pure reminder text, no ability of their own beyond the keyword. Nine more Reserve-keyword cards found in the same audit are deferred, each needing something else first (see the Reserve primitive row above and `docs/CARD_INVENTORY.xlsx`'s Blocker notes).

Follower wave 2 ([#148](https://github.com/alfredoh7/l5r-emperor/issues/148)) shipped 11 cards after auditing all 116 not-yet-imported Follower-type cards for ones needing nothing beyond already-built engine pieces: Akodo Regulars/Heavy Chargers (discard a card, boost own Force by its Focus Value; Heavy Chargers also gated "if this card is opposed", reusing Shinjo Horibe's `Army(1-player, province).Any()` check), Cavalry Flankers/Murderous Thieves (bow self, plain Melee Attack; Cavalry Flankers also gated to the Attacker only via `_state.ActivePlayerId`), Dark Naga Scouts/Horse Archers (plain Ranged Attack, Stalking Tiger's exact shape), Hiruma Sniper (plain Ranged Attack gated on the existing Reconnaissance primitive, matching `training-reconnaissance-strike`'s precedent), Veteran Advisor/Hired Legion (`Draw(player)`, the latter also bowing itself), Naga Remnants (bows a target enemy attachment via the pre-existing `enemy-attachment` category), Spitting Llama (a flat Force penalty via the pre-existing `enemy-force` category). Each needed at most one new one-off `Require` condition reusing an existing state check, never a new mechanism. The other 105 audited Followers are blocked on a real gap, most commonly (by card count): no Equip-time entry hook for "After this Follower enters play, ..." text (only Purchase() has one), no static Follower-Force hook (`CardForce` only reads a `PersonalityForce`-style Effect for Personalities), no "Will only/not attach to X" enforcement at Equip(), and no generic "without attachments" target filter. See the issue for the full per-card breakdown and gap ranking.

Follower wave 3 ([#174](https://github.com/alfredoh7/l5r-emperor/issues/174)) shipped 28 cards after re-auditing all 105 Followers Wave 2 left blocked against the primitives available as of the aggregate/group Force effects (Senior Infantry Legion, Ashigaru Elite, Utaku Elite Guard — all three now wired to their real cards) and province adjacency. New small additions along the way, each reused across more than one card: `CardDefinition.AttachGrantsKeyword` (an attachment granting its wielder a keyword for as long as it stays attached — Commander's Steed/Conqueror, Seppun Heavy Elite/Elite; the "Attachment"-duration `GrantedKeyword` lifecycle already existed but had never been exercised by a published card), a destruction-triggered Honor gain checked at both destruction paths (`DestroyedDuringBattleBonus`, Disciples of Ganesh), a keyword-based unit-scoped variant of `UnitFollowerBoost` (Aulus's "Legionnaires in this unit," alongside Senior Infantry Legion's type-based one), a Melee-only targeting immunity folded into the existing Attack validation (Seasoned Ashigaru), a Force-swap effect and a compound OR/controller-scoped Target category (Daifuke; Bounty Hunter's "attachment or dishonorable Personality"; Rumormonger's "a Personality whose controller controls a Dishonorable Personality"). Moto Gunso composes two of this session's own primitives directly: a multi-target `ApplyModifier` loop scoped by the just-built `AdjacentProvinces`. "Political" card text turned out not to be a blocker at all — Rumormonger and Soshi House Guard's "Political Open"/"Political Battle/Open" map onto the already-existing `Open`/`BattleOrOpen` Timing values verbatim, confirmed against Doji Shunya's own already-published "Political Limited" card. The other 77 audited Followers remain blocked on a real gap, most commonly (by card count): a new Reaction trigger the engine doesn't generalize yet (after an opponent's action targets a card in this unit; after this card bows; after a battle resolves; after a keyword-tagged action resolves; each turn begins — the largest single cluster), card creation from nothing (a new Follower/Personality instance, distinct from the Token primitive), Dueling/Focus Effects (not started at all), Rings (not started), a control-transfer mechanic (explicitly deferred since Loyal), attachment Transfer, deck/discard-pile search, Invest, a performer/wielder-keyed Attack-strength axis, and a handful of one-off single-card gaps (Dishonor-as-an-action, a unit-Force-total comparison target, cost-ignoring Equip, a compound multi-keyword attach restriction). See the issue for the full per-card breakdown.

Follower wave 4 ([#177](https://github.com/alfredoh7/l5r-emperor/issues/177)) shipped 3 cards, each wired for its own new engine primitive: Destrier (the passive Attack-strength defense modifier, Scope Self), Singh Remnants (the same primitive, Scope Unit and Ranged-only, plus the new "any Personality enters play" Reaction letting it attach itself from hand or a discard pile), and Clay Kshatriya (the Invest keyword mechanism). Unblocks Elephant Cavalry and Shieldman's own passive-defense half (both still need a separate remaining gap — "grant keyword to whole unit" and a Maneuvers-assignment restriction, respectively) — see their updated `docs/CARD_INVENTORY.xlsx` Blocker notes.

Follower wave 5 and Item wave 1 ([#179](https://github.com/alfredoh7/l5r-emperor/issues/179)) shipped 3 more `AttachGrantsKeyword` carriers: Scourge of the Sea (Naval, no ability of its own — Follower wave 5), and the first two ability-bearing Item-type cards published, Justice of the Crane (Magistrate, plus a new Battle Dishonor action) and Unparalleled Sword (Kensai, plus a plain Melee 4 attack) — Item wave 1. Also fixes a real bug in Follower Wave 3's original Seppun Heavy Elite wiring (see the `AttachGrantsEliteEffect` primitive row above) and closes the "Dishonor-as-an-action" gap noted against oracle-l5r-10683 in Wave 3's audit (that card still needs a separate "may not attack" restriction flag).

Strategy wave 2 ([#181](https://github.com/alfredoh7/l5r-emperor/issues/181)) shipped the three cards behind the Additional Action primitive: Again! Import wave: Strategy cards blocked only by the keyword-satisfaction primitive ([#144](https://github.com/alfredoh7/l5r-emperor/issues/144)/[#146](https://github.com/alfredoh7/l5r-emperor/issues/146)) shipped 4 cards after a catalogue-wide search for "performing/target [Keyword]" phrasing turned up 386 scan-verified candidates (259 Strategy-type). Immovable Object is the primitive's own worked example — its printed "Battle/Open" dual timing needed a new `BattleOrOpen` `AbilityDefinition.Timing` value (usable in either phase, no army-presence/at-battle blanket checks, matching that its printed text carries none), and its second ability needed one new one-off Target comparison (`enemy-force-lower-than-performer`, against the Performer's Force). Blind Rage needed nothing beyond the just-built generic Performer category itself. Chokehold needed the generic Performer category plus one new one-off Target comparison (`enemy-personality-chi-lte-performer`, against the Performer's Chi). Unorthodox Attack needed *nothing new at all* — it reuses the pre-existing `own-unbowed-samurai-at-battle` Performer and `enemy-force` Target categories verbatim. Two of the four needed a Text correction from the fetched catalogue record's scraped wording, checked against the actual scanned card image, never silently trusted. ~52 further "clean" Strategy candidates (each with its own small additional wrinkle) and ~200+ with a bigger gap remain untriaged in detail; Personality/Spell/Stronghold-type candidates using these keywords are untouched. See the issue for the full breakdown.

Import wave (Cavalry/Conqueror/Tactician, [#111](https://github.com/alfredoh7/l5r-emperor/issues/111)) shipped 7 cards after searching all 228 not-yet-imported cards carrying Cavalry, Conqueror, Tactician, or Kensai: Daigotsu Kendo (pure Conqueror reminder text), Ikoma Natsu (Cavalry, plus a "won't be controlled by an opponent" restriction that's currently inert since no control-transfer mechanic exists), Mirumoto Reiyu (Force penalty equal to her own current Force, reusing the existing `enemy-force` target category), Shinjo Horibe and Doji Atsumichi (bow-or-straighten a Personality, same shape as `paid-bow`/`paid-straighten`, gated respectively on "opposed" and "lower Personal Honor than the source" — two new one-off target/condition checks), Tetsuo (destroy an attachment via the existing category, plus destroy an enemy Personality with fewer Weapons than himself — another new one-off comparison category), and Moto Shunsuke (a new `force-max-dead-pile` Effect — the largest single per-player pile of dead Personalities — plus the already-built `MakeDead` primitive with an added owner restriction). Only 30 of the 228 candidates had downloaded reference scans; of those, two more (Nishimura, Utaku Elite Guard) were judged achievable but deferred as riskier — Nishimura needs two new one-off target categories plus a "may" sub-choice reinterpreted as a separate ability, and Utaku Elite Guard needs a new *aggregate* Force bonus granted to other cards sharing an army, not just a self-referential one. The other 21 of the 30 are genuinely blocked (Dueling, additional Battle actions, Created cards, province-strength modification, several new Reaction triggers, attachment cost discounts, mid-battle movement, ability removal, target redirection).

Triaging this wave also surfaced a real gap in the just-shipped Kensai primitive: Sandayu's reminder text revealed that a `Two-Handed` Weapon overrides both the Kensai and Kama two-Weapon allowances entirely (fixed in [#109](https://github.com/alfredoh7/l5r-emperor/issues/109) before this wave shipped).

Import wave 1 ([#95](https://github.com/alfredoh7/l5r-emperor/issues/95)) shipped 5 cards (Shinjo Eun-Sahng, Shosuro Konishi, Tsuruchi Kosoko, Tsuruchi Isas, Stalking Tiger) whose only blocker was the Ranged/Melee Attack primitive, plus a small additive `PendingAttack.SourceId` extension so a card's own post-attack effect (Isas' "move him home") can find the exact performing instance.

Import wave 2 ([#97](https://github.com/alfredoh7/l5r-emperor/issues/97)) shipped 2 cards (Bayushi Kahoku, Asako Ume) after widening `AttackStrength` to take the candidate target (unlocking target-dependent strength, e.g. Kahoku's "+2 if the target is dishonorable") and adding an always-on `PersonalityForce` Effect hook (`force-with-spell`, `force-if-enemy-dishonorable`) alongside the existing attacking-only Effects.

Sixteen further Tier 2 candidates were triaged for import wave 2 and did not ship this round. Five need only the same target-dependent-strength/Force extensions wave 2 already built, but had no downloaded reference scan (same Oracle of the Void API blocker as wave 1's remaining nine): Akodo Kamina-exp, Horseback Warriors, Shiba Shirou, Cursed Relic, Isawa Kaname. Sankaku-Yari is the same shape as Horseback Warriors but also exposed a real gap: an Item's Battle ability has no check that its wielding Personality is actually at the current battlefield (only Personality-sourced abilities get that check today). Nine further Tier 1 candidates from wave 1's triage remain blocked purely on scans, not mechanics: Dark Naga Scouts, Horse Archers, Shikaro, Isawa Taiken, Murderous Thieves, Shinjo Sujikaro, Moto Ming-Gwok, Bayushi Higaonna, Cavalry Flankers.

Next content candidates should be chosen by which mechanic they'd exercise, per the "build the rules engine as we go" approach — e.g. the recurring "you do not lose Honor from [category] cards you own" pattern (6+ Strongholds) is the next highest-leverage primitive by card-count once picked up again.
