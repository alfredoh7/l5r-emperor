## 1. Request and findings in one page

Mendon asked for the scans printed "May not be included in decks." (Oracle type `Proxy`, not a rules card type) to be reviewed and wired as the cards that a "create a card" effect creates, behaving as the real type they stand for, using the Lion Ancestor (wired) and Water Bo (created by the Spell Bo of Water, not wired) as the two examples.

## 2. The created-card resolver

An ability that creates a card declares **what its printed text says the card is**, as data: `AbilityDefinition.Creates`, a `CreatedCardSpec` (type; Force, Chi, Personal Honor when printed; the exact keyword set; the ability text when the text prints one; an explicit `ProxyId` only when the rest of the spec fits several scans). The engine finds the scan that is that card and instantiates it.

- **Scans are ordinary published cards.** Each scan is published in a wave file as its real type (Lion Ancestor a Personality, Water Bo an Item) with `CreatedOnly: true` (the flag Kitsu Akai's Lion Ancestor already carried). It has art, keywords, Force and abilities like any card, so the created card behaves exactly as its type does: a created Weapon attaches, grants its bonuses and has its own action; a created Personality is a Personality (unit membership, Force, Chi, Honor, abilities).
- **Resolution is by data.** `CreatedCards.Resolve(spec)` returns the one `CreatedOnly` definition whose type, stats and keyword set (order and case ignored) fit and whose text contains the spec's ability text (ignoring case and punctuation). No scan, or several, throws `CreatedCardResolutionException` naming the spec and the candidates. A named `ProxyId` must still fit everything else the spec says, so a wrong pairing fails too.
- **Failing loudly.** `CreatedCards.Verify()` resolves every ability that has a `Creates` spec (and checks the engine can create that kind of card); a test asserts it is empty, so a creator with no scan, an ambiguous scan or a kind of card not built yet is a test failure listing the creator by ability id.
- **Instantiation** (`MatchEngine.ExecuteCreate`, the third data-driven default branch beside `Attach` and `Branch`): a Personality is created at home through the entry sequence Kitsu Akai already used (no cost, no Proclaim, no refill; the creator's own "After X enters play" window is not clobbered when the creator is such a Reaction); an Item, Follower or Spell is created attached to the Personality the ability targets. Its id is `created-NNNN` from a per-match sequence (replay-safe); the event log says `cardCreated`.
- **Attach legality is Equip legality.** The chosen Personality must be one the created card could be equipped to (`RequireAttachable`: "will only attach to", Honor Requirement, one Armor and one Weapon, two Weapons with Kensai or a Kama, Unique/Singular), judged when the action is offered, so an offered command is one that resolves.
- **Once per game** is a new `AbilityDefinition.OncePerGame` flag (per source card, never resets; Border Keep's refresh, which had a hard-coded id check, now uses it).
- **Created cards leave the game, never a pile.** Personalities were already redirected in `DestroyUnits`. Everything else (an Item destroyed with its host, a card destroyed alone, returned to a hand, shuffled) is caught by `RemoveCreatedCardsLeftInPiles`, run after every command: a created card found in a discard pile, a hand or a deck is removed from the game, so it can never be drawn, searched for or recovered.
- **Adding a created card later is data plus a manifest.** Publish its scan through the packager (a `CreatedOnly` override, the real type, its abilities), pin the wave with `pin_wave_ids.py`, and give the creator a `Creates` spec. Code is only needed when the scan carries an ability or trait the engine does not have (as for any card), or the kind of card cannot be created yet (`CreatedCards.Creatable`: Personality, Item, Follower and Spell since #390, Holding and Terrain since #407; no card creates a Region, and The Golden Plains' Terrain is the only Strategy).
- **Re-expressed, not changed:** Kitsu Akai (Lion Ancestor), Kitsune Ohsuki and Kitsune Tokoru (their tokens) no longer name a scan in code; their specs resolve to the same three definitions and their existing tests pass unchanged. Kyuden Hida's synthetic scenario-only Scout is not converted: two scans fit it (question 2).

## 3. The two examples

**Lion Ancestor.** `kitsu-akai-create` declares `Personality 2F/2C/3PH [Lion Clan, Samurai, Ancestor, Spirit]`; the resolver finds `oracle-l5r-9785` (personality-wave-17, its art `Content/Published/oracle-l5r-9785.jpg` already shipped from the Embers of War/Emperor Edition scan; no download). Behaviour is the pre-existing behaviour: created at home, face up, straightened, no window, once per turn, coexists with other copies, removed from the game when destroyed (after ordinary destruction, including the Dishonorable-death Honor loss).

**Water Bo, created by Bo of Water.** Both are new (item-wave-5, spell-wave-10):

- *Bo of Water* (oracle-l5r-1084, Second City #90; Spell, Cost 2, Focus 3, Water): "While this Shugenja is Water, he contributes Force to his army even if bowed." is the Elite effect (never the Elite keyword) given to a Water wielder, live, through `CardDefinition.AttachGrantsEliteEffectWhileWielderHas = "Water"`. "Limited: Once per game: Create a +2F/+0C Water * Weapon Item with the ability ... and attach it to one of your Personalities" is `bo-of-water-create`: a Limited action of the acting player, in the Action phase, targeting one of your Personalities in play; `OncePerGame` per Spell card (two Bo of Water are two uses); `Creates` = `Item +2F/+0C [Water, Weapon]` with the ability text as printed.
- *Water Bo* (oracle-l5r-10026, Second City, the Proxy scan; Item, Cost 0, +2F/+0C, Water * Weapon, "May not be included in decks." and "Battle: Target an enemy card without attachments: Bow it"). Published as an Item (`CreatedOnly`), ability `water-bo-bow`: an enemy-card bow (Stalwart negates it like any bow), no cost, once per turn, performed by its wielder, so its wielder must be at the battle. That presence rule is now the general rule for every Battle ability on an attached card (core rules: an action on an Item, Spell or Follower is performed by the Personality it is attached to): before, it was a per-id list (`scouring-flood-move-home`, `nightingale-blade-bow`, ...) that other Items such as Unparalleled Sword were not on; abilities that move a Personality to the battle (`MovesToBattle`) stay exempt. The whole core suite (787 tests with main merged) passes with the general rule.
- *Result*: the created Water Bo is attached to the chosen Personality, adds +2F to him, may not go onto a Personality that already carries a Weapon (unless Kensai or Kama), is public information (both players' views carry its definition and art key; no hand, deck or random number is touched), is removed from the game when destroyed or when its host dies, and never appears in a discard pile.
- *Catalogue discrepancy for Bo of Water.* The scan prints "**Limited:** Once per game: Create ..." and the ability "Battle: Target an enemy card without attachments: Bow it"; the catalogue's current text says "Water Limited: Once per game, create ..." and "Battle: Bow a target enemy card without attachments". The published text and the spec follow the scan, and the "Water" before Limited is not treated as a requirement on the Shugenja (the scan does not print it). Question 8 asks Mendon to confirm.

## 4. Scans never enter a deck

| Where | Guard |
|---|---|
| Deck workshop (`DeckWorkshop`) | A created-only card (`CreatedOnly`) or a raw Oracle `Proxy` scan is not in the pool: it cannot be added, `Load` rejects a deck file naming it as an unknown card, and it is never counted. The old soft warning ("cannot be included in decks") is gone because it can no longer be reached. `DeckWorkshop.MayBeInDeck` is the one predicate. |
| Match setup | `MatchEngine.CreatePublished` refuses any deck that lists a created-only card before the match exists; `PublishedContent.Load` refuses a published snapshot whose deck lists one. |
| Drawing, search, discard pile effects | `RemoveCreatedCardsLeftInPiles` (above): a created card is never in a hand, deck or discard pile at the end of a command. |
| Counts | `CardCatalog.PlayableFromDecks` (published, not created-only) is the "playable from decks" set; `CatalogueMatchesDisk` still requires the created-only cards to be published files (they are published cards with art), and the per-wave manifests pin them. |
| Deck data | `content/deck-pool.json` (built by `build_deck_pool.py`, which excludes the Oracle `Proxy` type), `content/deck-library.json` and `content/decks/*.json` list none of them; a test asserts it for every created-only id. |

15. **Basic Lesson's Stronghold restriction** (asked in the scan-request PR, section C): "Basic Lesson restricts the player's stronghold from straightening again on the turn that Basic Lesson is played. It ends in the End phase of the turn that Basic Lesson is played." Built in #411: `CardInstance.StraightenLockedTurn`, a whole-turn restriction beside the one-shot `StraightenBlockedTurn`. While it holds, `Straighten()` (the one choke point every effect that straightens a card goes through) refuses; an action whose only effect is a straighten (`StraightensOnly`: Jinn-Kuen's Political Open, Kodo, Munefusa, ...) is not offered against the card and is refused with the reason; an action that also does something else (Defensive Stance's +3F) resolves without the straightening. It is compared with the turn number, so it stops holding when the turn moves on (after the End phase) and the automatic Straighten phase, which is not an effect, is untouched. Only the Stronghold of the player who played Basic Lesson is restricted, whoever tries to straighten it. **Printing note:** the period scan prints only the two actions (no Stronghold clause); "Negate your Stronghold's straightening (this turn)" is the current Oracle text, so the published text is the catalogue's and the ruling above is what it means. ## 8. UI

The client needs nothing new to show a created card: the view already carries `CardView.Definition` (with `ArtworkKey`, published art `res://Content/Published/<id>.jpg`, and `CreatedOnly: true`), and a created card's instance id starts with `created-`. A "created" label would be cosmetic and can read `Definition.CreatedOnly`; no issue for Alfredo is opened. Note for the deck builder: created-only scans are not in `DeckWorkshop`'s pool any more, so `Draft.Adjust` on one throws `KeyNotFoundException`; the client's family filter (`Dynasty`/`Fate`, scans are `Other`) never offers one, and if that filter ever changes the collection must skip `Definition.CreatedOnly` and the raw type `Proxy` (use `DeckWorkshop.MayBeInDeck`).
