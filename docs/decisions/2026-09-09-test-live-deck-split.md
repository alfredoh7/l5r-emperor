# Automated tests use a frozen deck, decoupled from the live playtest deck

Status: Accepted, 2026-09-09, by explicit request from Mendon.
Lane: rules. Issue: https://github.com/alfredoh7/l5r-emperor/issues/115
PR: https://github.com/alfredoh7/l5r-emperor/pull/116

Editing the pinned Lion/Crane deck for manual playtesting (issue #113: swapping in Ikoma Natsu and Doji Atsumichi) silently broke ~15 unrelated tests that had come to depend on the exact composition of `PublishedContent.Snapshot` -- some as generic enemy-Personality stand-ins, one (`Setup`) checking intrinsic setup mechanics that happened to be readable off the live deck. Going forward:

- `CardCatalog` remains the single, permanent static database of card definitions. A card is never removed from it except by explicit direction that it is not Emperor-legal -- swapping a card out of the *live* deck moves its definition to `VanillaWave1` (if ability-free) or another wave, it does not delete it. Ikoma Takakura and Doji Tatsuki (cut from the live deck in #114) were restored to `VanillaWave1` under this policy; they had been silently deleted from the catalog entirely, which is what this decision closes off going forward.
- `PublishedContent.Snapshot` / `MatchEngine.CreatePublishedMatch()` / `content/published/lion-crane-v1.json` remain exactly what they are today: the live app deck, shipped to the client and used by `RoomManager` for real rooms, freely editable for manual playtesting.
- `PublishedContent.TestSnapshot` / `MatchEngine.CreatePublishedTestMatch()` / `content/published/lion-crane-test-v1.json` are new: a one-time frozen copy of today's pinned Lion/Crane 40/40 deck lists, used only by the C# test suite (`PublishedTests.cs`'s generic-mechanics tests, `Program.cs`'s `BowedPersonalityResolution`). It is never auto-regenerated by `package_published.py`. Its own embedded `Cards` are deliberately not merged into `CardCatalog` -- only the deck *lists* (which ids, how many) are pinned; card behavior for those ids still resolves through the one shared `CardCatalog`, so a genuine bug fix to a card's wiring is still reflected in tests.
- A few tests deliberately still exercise the *live* deck on purpose, as smoke tests of whatever is actually deployed: `OfferedActions`, `Replay` (`PublishedTests.cs`), and the AI project's published-mode game simulation. A card newly swapped into the live deck should still get its abilities and full-game playability checked somewhere, just not by tests whose actual subject is unrelated engine mechanics.

This is a starting point, not a final architecture -- the user explicitly said this can evolve once the full application (client included) is tested more robustly. The client (Godot) and `RoomManager`'s room-scenario gating are unchanged by this decision.
