# P10: keyword-rule registry, gain blocks, element replacement, permanent Clan alignment (#695)

Status: built as an engineering primitive, engine only. No card is wired and no scan is added; every proof is a Core test on fixture rules and per-instance definitions (`CardInstance.Printed` with an Effect starting `training-p10-`). The points under "Readings for Mendon to confirm or correct" are readings, not rulings.

Specification: section P10 of [the primitive prompts](2026-10-05-remaining-unwired-primitives-prompts.md), narrowed by the coordinator for this pass. It reuses [P9's](2026-10-06-672-p9-stat-terms.md) condition vocabulary and its re-entrancy convention.

## What was built

All in `src/L5R.Core/KeywordRules695.cs` (the primitive) and `KeywordRules695Legacy.cs` (the four moved conditionals). Hook id `P10KeywordRules`, priority 16500; state `MatchState.KeywordRules`, `JsonPropertyOrder(22500)`.

1. **`EngineHooks.KeywordRule`**: `Func<MatchEngine, KeywordRuleContext, KeywordRuleResult?>`, consulted once in `Keyword()` (`ConsultKeywordRules`) just before the printed and granted keywords are read. It answers `Granted`, `Suppressed` or `null`; the first `Suppressed` wins, then any `Granted`. A `Suppressed` answer beats a printed or granted keyword but not a permanent removal (`KeywordRemoved` runs first).
   * **`KeywordRuleCatalog`**: the data form. `KeywordRule(Id, Scope, Keywords, SourceEffect | SourceCardId, Effect, AllOf, SourceAnyOf, InAndOutOfPlay, ExcludeSource)`. Scopes: `Self`, `Unit`, `Army`, `Controller`, `All`. `Register`/`Unregister` are static (tests register fixtures and remove them).
   * **Conditions.** `SourceAnyOf` is P9's `TermCondition[]` (any one holds), evaluated on the source card by P9's own `StatTermConditionHolds`, so `OtherPlayerIsClan`, `ControlsPersonalityWithKeyword`, `EnemyLeaderHasFavor` and the rest work unchanged. `AllOf` is `KeywordCondition[]` (all hold) about the card the keyword is asked of: `SubjectHasKeyword`, `SubjectLacksKeyword`, `SubjectIsHuman`, `SubjectIsType`, `SubjectIsClan`, `ControllerIsClan`, `SubjectHasAttachmentOfType`, `NotControllersTurn`, `SourceFollowerCount`, `ControllerControlsRingWithAskedKeyword`, `SubjectInPlay`, `SubjectAttached`.
   * **Live and guarded.** Nothing is cached or written on a card. A (card, rule) pair being evaluated counts as nothing inside its own evaluation, as P9 does, so rules that read each other's keywords cannot loop (tested: a two-rule cycle, and a rule reading its own keyword).
   * **Hot path.** `Keyword()` adds one dictionary lookup and a few integer tests when no rule names the keyword and nothing is stored; a test measures 0 bytes per consult over 5000 calls, with and without a stored block on another card. Rules for Cavalry and Naval exist (the legacy four), so those two keywords also pay a loop over the unit's cards for the Unit-scope rules: structural id comparisons first, `Definition` only for the unit's own cards.
2. **Gain blocks** (`KeywordGainBlock`): "will not gain" by keyword list and/or class (`clan`, `element`, `any`), on one card or on every Personality a player controls, lasting while a source card is in play (or for the game when none is named). Honoured by `GrantKeyword`, `PermanentlyCopySpell`/`PermanentlyCopyPersonality`, the Fukuzo-style copy (`CopyableKeywords` and the grant), `ClanAlignments` (so Seppun Nagi's and Atosa's static alignments and permanent grants), `WithControllerClan` (a created card's controller Clan, including Seeds of Decay batch 4's), and a live-granted keyword (`Keyword()` answers `Suppressed` for a blocked keyword that is neither printed nor granted). A block never removes a printed or already-granted keyword.
   * **Source leaves play.** A block whose source is out of play is removed, not just ignored, on the next keyword read (`PruneKeywordRuleState`), so a source that leaves and comes back does not revive it (tested). `RemoveKeywordGainBlocks(sourceId)` removes a source's blocks explicitly.
3. **Element replacement** (`ElementReplacement`): a map from one element keyword to another on a card, read by `Keyword()`. The elements the card has without any replacement are computed first (a bypass flag on that card), then mapped in registration order, so rule-granted elements and chains (Fire to Water, Water to Air) map too. Every element read in the engine goes through `Keyword()`, so Spell eligibility (`AttachmentLegalTarget`) follows (tested). It lasts while its source stays in play and attached to the card; it is swept like a block.
4. **Permanent Clan alignment** (`GrantClanAlignment`, `RemoveClanAlignment`): a `ClanGrant` read by `Keyword("Crane Clan")` and by `ClanAlignments` (through `GainedClanAlignments`), so Loyal, Unaligned (computed, never printed; R-015/R-016: Ninja is a keyword, not a Clan) and the Clan discount see it. The existing `RemoveClanAlignments` removes granted alignments too (it now also drops the grants); a removed alignment can be given again. "Permanent" means for the rest of the game, like a permanent copy: the grant is not cleared when the card leaves play (see readings).
5. **Live conditionals moved onto the channel** (`KeywordRules695Legacy.cs`), each the same test as the branch it replaced, with its existing tests passing unchanged: Isawa Kojiro's Naval while he has a Spell (`naval-while-has-spell`), Moto Jun-Ni's unit Followers' Cavalry (`unit-followers-cavalry`), Tamori Yayu's Cavalry when it is not your turn (`cavalry-force-while-not-your-turn`), Hida Watari's sole-Follower Cavalry (`watari-sole-follower-cavalry`; `WatariGrantsCavalry` deleted). Kojiro's old branch returned its answer outright, so a later source could not add Naval to him; none can (every later source names its own card Effect or another keyword), so the move is exact.

## API for a card-wiring agent

```csharp
// A trait that grants keywords (module initializer of the card's file). Chun: "Human Personalities in Chun's army have Naval."
KeywordRuleCatalog.Register(new("chun-naval", KeywordRuleScope.Army, ["Naval"], SourceEffect: ChunEffect,
    AllOf: [new(KeywordConditionKind.SubjectIsType, "Personality"), new(KeywordConditionKind.SubjectIsHuman)]));
// Uji's Saboteurs: "has Naval while he is Crane Clan."  Self scope, no source needed beyond his own Effect.
new KeywordRule("ujis-naval", KeywordRuleScope.Self, ["Naval"], SourceEffect: UjiEffect, AllOf: [new(KeywordConditionKind.SubjectIsClan, "Crane")]);
// Elephant Cavalry: "cards in this unit have Cavalry."  Unit scope; the source is the attached card.
new KeywordRule("elephant-cavalry", KeywordRuleScope.Unit, ["Cavalry"], SourceEffect: ElephantEffect);
// The Inevitable Grasp of Conquest: "Your Personalities have Conqueror."  Controller scope, source in play (a Celestial is in play).
new KeywordRule("grasp-conqueror", KeywordRuleScope.Controller, ["Conqueror"], SourceEffect: GraspEffect, AllOf: [new(KeywordConditionKind.SubjectIsType, "Personality")]);
// Drawing on All Things: "This Shugenja has the element keywords of every Ring you control."  A Spell on the Shugenja: Unit scope.
new KeywordRule("drawing-elements", KeywordRuleScope.Unit, ["Air", "Earth", "Fire", "Water", "Void"], SourceEffect: DrawingEffect,
    AllOf: [new(KeywordConditionKind.SubjectIsType, "Personality"), new(KeywordConditionKind.ControllerControlsRingWithAskedKeyword)]);
// "while another player is Clan X" is P9's condition on the source: SourceAnyOf: [new(TermConditionKind.OtherPlayerIsClan, "Crane")]
// A rule that takes a keyword away: Effect: KeywordRuleEffect.Suppress.

// "Will not gain Fallen or Shadowlands" (Ikoma Ayumu - exp): while his card is in play.
engine.AddKeywordGainBlock(sourceCardId: ayumu.Id, cardId: ayumu.Id, playerId: null, keywords: ["Fallen", "Shadowlands"]);
// "Will not gain a Clan Alignment" (Iweko Seiken, Iweko Shibatsu): classes: ["clan"]. "Your Personalities will not gain ...": playerId: owner, cardId: null.
engine.AddKeywordGainBlock(sourceCardId: iweko.Id, cardId: iweko.Id, playerId: null, classes: ["clan"]);
// "Replace Fire with Water on this Shugenja while this Spell remains attached" (Blood of Isawa's Tribe); the caller validates and records the player's choices.
engine.ReplaceElementKeyword(shugenja.Id, "Fire", "Water", spell.Id);   // RemoveElementReplacements(spell.Id) removes them early
// "Permanently give your target non-Loyal, face-up Personality your Clan Alignment" (Suikihime's Sanction): one call per Clan of the controller's Stronghold (ControllerClans).
engine.GrantClanAlignment(target, "Crane", source.Id);                    // false when a block refuses it
engine.RemoveClanAlignment(target, "Crane");                              // or the existing RemoveClanAlignments(target) for all
```

A feature that needs a different shape registers its own callback: `EngineHooks.KeywordRule.Register("<id>", priority, static (engine, context) => ...)`.

## Left out, and why

- **"Will not gain any keyword that ..." with a free-form predicate.** Blocks name keywords or the classes `clan`, `element`, `any`. A card whose text names another class needs a class added; none of the listed cards does.
- **An "any of" subject condition.** `AllOf` is a conjunction. The False Path's "Monk and Fudo Personalities have Monk and Fudo" is two rules (Monk granted while the card has Fudo, Fudo granted while it has Monk); the re-entrancy guard makes the pair work from printed keywords, as the cycle test shows.
- **The other conditional grants in `Keyword()`**: `PromoEmperorNaval`, `WlItemsMiscKeywordGranted`, `PromoItemsKeywordGranted`, `UnmeiMirrorsKeyword`, `PromoGrantsKeyword`, `WlPersTornGrantsKeyword`, `OchiaiGrantsDuelist`, the static Seeds of Decay rules. Each needs a condition the vocabulary lacks (attached Item with a given Effect, mirrored keyword of another Personality, "while defending") or has its own guard; moving them would be a rewrite with no behaviour to gain. Left in place.
- **Keyword lists read directly rather than through `Keyword()`**: `SharesNoKeywords` (Dueling.cs), `KeywordCountExceptSoulOf` (EmperorRemainingB.cs) and `CurrentKeywordList` (the source of a copy) enumerate printed plus granted keywords, so they do not see rule-granted or replaced keywords. That was already so for the four moved conditionals.
- **An unguarded grant**: `EmperorP5Hidden.cs` adds a copied keyword to `GrantedKeywords` directly; it does not pass `GrantKeyword`, so a block does not stop it. It is not a listed path; if a card needs it, route it through `GrantKeyword`.
- **A replay test that runs commands.** No command writes these stores yet (no card is wired). Save and replay safety is tested as: the stores are in the saved state, a JSON round trip and `Clone` are byte for byte, an engine rebuilt from the saved state answers identically, and two engines driven through the same calls end with the same state.

## Readings for Mendon to confirm or correct

1. **A `Suppressed` answer beats a printed keyword.** Element replacement needs it (a printed Fire is no longer Fire). Gain blocks use it only for keywords that are neither printed nor granted. A permanent removal still wins over any rule.
2. **A live-granted keyword is a "gain".** "Will not gain Fallen or Shadowlands" also stops a static or conditional rule from giving it (for example Seppun Nagi's Clan alignment, a Unit rule), not only an action's one-time grant. A keyword already granted before the block stays.
3. **A block ends when its source leaves play**, and does not return when the source does (a new entry is a new card for this purpose). A block with no source (a permanent "will not gain") lasts for the game. A printed trait ("will not gain a Clan Alignment" on Shibatsu) is modelled as a block sourced from his own card, so it applies while he is in play: a Personality in a province is not in play and can be given an alignment. If it should also bind out of play, register the block with no source when he is recruited and leave it, or make it a rule on the card.
4. **"Permanently give ... Clan Alignment" lasts for the game**, including after the card leaves play and re-enters, like the permanent copies (which write the card's printed values). `RemoveClanAlignments` (Discovering a Conspiracy) is unchanged in how long it lasts: its record is still cleared when the card re-enters play, where a granted alignment would not be, so the two differ. A granted alignment that `RemoveClanAlignments` removed is dropped for good.
5. **Element replacement leaves non-element keywords alone** and maps only the five elements; it replaces keywords, not text, so "in this Shugenja's keywords or text" (Blood of Isawa's Tribe) is the wiring agent's to validate as the legal choices.
6. **Unit scope** is the Personality and every card attached to him (Followers, Items, Spells), so "cards in this unit" includes the source. A card that is not attached and not a Personality has no unit.
7. **Army scope** is the Personalities, and the cards attached to them, at the same battlefield on the same side; a Personality at home is in no army. Chun's own Naval counts (he is Human and in his own army); use `ExcludeSource` for "other".
8. **Self rules are read in and out of play** (a keyword, like Yayu's), unlike the other scopes, which need the card in play unless `InAndOutOfPlay` is set; add `SubjectInPlay` to a Self rule that is a trait working only in play.
9. **Controller** is the card's current controller (`OwnerId`, which follows control), including for a card whose control has been taken.
